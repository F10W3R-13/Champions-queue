# Airtable 쿼터 고갈 — 10/1 이전 재가동용 임시방편 런북

> 작성: 2026-09-09. 전제: 현재 워크스페이스의 월간 API 쿼터(Free 1,000건) 소진,
> 리셋은 10/1. 수요 때문에 그 전에 재가동해야 함. 이 문서는 그 갭을 메우는 3단계 계획이다.

## 배경 사실 (2026-09-09 검증)

- 에러: `429 PUBLIC_API_BILLING_LIMIT_EXCEEDED` — 워크스페이스 단위 월간 한도. 토큰은 유효.
- Free 플랜: 1,000 API 호출/월, 하드스톱(구매 불가), 매월 1일 리셋.
- 봇 코드는 이미 예산 안으로 줄임: reconcile 12h(월 ~480건) + 이벤트성 호출만.
  즉 **코드가 아니라 워크스페이스 예산이 문제**다.

## 옵션 비교

| 옵션 | 효과 | 비용 | 판정 |
|---|---|---|---|
| A. 새 워크스페이스에 베이스 복제 | 복제본 = 신규 워크스페이스 = **별도 1,000건 예산**. UI 복제는 API 쿼터 안 탐 | 무료, 30분 작업 | ✅ **권장 (10/1 전 재가동)** |
| B. 10/1까지 대기 | 예산 리셋 | 재가동 지연 | 수요가 있으므로 기각 |
| C. Team 플랜 업그레이드($20/월) | 100,000건/월 | 월 $20 | 장기 대안. A와 충돌 없음 — 나중에 원본 워크스페이스를 업그레이드하고 복제본을 합치면 됨 |
| D. 로컬 DB 이관 | 쿼터 문제 소멸 | 에어테이블 UI·스태프 워크플로 전부 재건 | 시즌 안정화 후 검토 |

## 실행 절차 (옵션 A)

### 1단계 — 사용자가 Airtable UI에서 (API 호출 없음, ~10분)

1. 현재 베이스("Champion's Queue Stats") → 우클릭/··· → **Duplicate base**
   - 위치: **새 워크스페이스**로 생성 (같은 워크스페이스 안에서 복제하면 예산을 공유하므로 반드시 새 워크스페이스)
2. 원본 워크스페이스는 그대로 두면 됨 (S1 아카이브 겸, 10/1에 예산 리셋되면 여유분)
3. 복제 완료 후:
   - 복제본 베이스의 ID(`app...`)를 기록 — URL에서 확인
   - 각 테이블을 열어 테이블 ID(`tbl...`)가 원본과 같은지 확인
     (Airtable은 베이스 복제 시 테이블 ID를 **보존하지 않는 경우가 있음** — 이때는 2단계에서 전부 덮어쓰면 됨. 어느 쪽이든 env 덮어쓰기로 처리 가능하게 코드를 이미 수정해 둠)

### 2단계 — 서버 .env 교체 (Apollo 패널, ~5분)

복제본 베이스로 포인터를 옮긴다 (코드 변경·재배포 불필요):

```
AIRTABLE_BASE_ID=app<복제본 ID>
# 테이블 ID가 복제에서 바뀌었다면 (복제본 베이스 UI에서 확인):
PLAYERS_TABLE_ID=tbl...
HP_TABLE_ID=tbl...
SND_TABLE_ID=tbl...
ALIASES_TABLE_ID=tbl...
TEAMS_TABLE_ID=tbl...
```

함께 반영할 재가동 설정 (로컬 .env에는 이미 반영됨):
```
DECAY_GATE_ENABLED=0        # 800 게이트 중단 (교찰 구조 + Day 1)
CURRENT_SEASON=S2
SEASON_START=2026-09-15
SEASON_END=2026-12-13
```

### 3단계 — 검증 (~10분)

1. Apollo에서 Restart
2. Discord에서: `/ign` (등록 확인 — Players 테이블 쓰기), `#results`에 테스트 스크린샷 2장 (OCR ingest 확인)
3. Airtable 복제본 베이스 UI에서 새 행 생성 확인
4. bot.log / staff-logs 채널에 429-billing 에러가 더 안 나오는지 확인

## 주의사항

- **원본 베이스를 지우지 말 것** — matcher alias, S1 기록의 원본이다. 복제본이 S2 라이브가 된다.
- 복제 시점 이후 원본에 수동 편집을 했다면 복제본과 diff가 생긴다 — 복제는 "지금" 기준.
- 새 워크스페이스도 Free면 예산 1,000건/월이다. 봇 소모(월 ~480건 + 이벤트)를 감안하면 S2 시즌 내내 여유. 단, **Airtable UI에서 수동 대량 편집 후 봇 reconcile이 따라잡는 시나리오**는 주의.
- 이 런북은 임시방편이다. 시즌 안정화 후 판단할 것: (a) Team 업그레이드 후 원본로 회귀·통합, 또는 (b) 다음 시즌 전환 시마다 신규 워크스페이스 복제 반복(세션 분리 효과도 있음).
